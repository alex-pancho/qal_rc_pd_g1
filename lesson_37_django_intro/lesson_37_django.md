## Архітектура веб-застосунків

Веб-застосунок — це програма, яка працює через браузер або інший HTTP-клієнт. Користувач відкриває сайт, надсилає запит на сервер, а сервер повертає відповідь у вигляді HTML-сторінки, JSON, файлу або іншого ресурсу.

Зазвичай веб-застосунок складається з кількох частин:
- клієнтська частина, тобто браузер;
- серверна частина, де виконується логіка;
- база даних, де зберігаються дані;
- шаблони, стилі, статичні файли та бізнес-логіка.

У навчальних проєктах на Django ми найчастіше працюємо з серверною частиною, базою даних і шаблонами. Django бере на себе багато рутинної роботи, щоб розробник міг зосередитися на логіці застосунку.

## Протокол HTTP

HTTP — це протокол обміну даними між клієнтом і сервером. Коли ви відкриваєте сторінку в браузері, браузер надсилає HTTP-запит, а сервер повертає HTTP-відповідь.

### Основні методи HTTP
- `GET` — отримати дані;
- `POST` — надіслати дані на сервер;
- `PUT` — повністю оновити ресурс;
- `PATCH` — частково оновити ресурс;
- `DELETE` — видалити ресурс.

### Структура запиту
HTTP-запит зазвичай містить:
- метод;
- URL;
- заголовки;
- тіло запиту, якщо потрібно передати дані.

### Структура відповіді
HTTP-відповідь містить:
- статус-код;
- заголовки;
- тіло відповіді.

### Приклади статус-кодів
- `200 OK` — успішно;
- `201 Created` — ресурс створено;
- `301/302` — перенаправлення;
- `400 Bad Request` — помилка у запиті;
- `401 Unauthorized` - відсутня авторизація;
- `403 Forbidden` — доступ заборонено;
- `404 Not Found` — сторінку не знайдено;
- `500 Internal Server Error` — помилка на сервері.

HTTP — це основа будь-якого веб-застосунку, тому розуміння запитів і відповідей дуже важливе для подальшої роботи з Django.

## MVT-архітектура Django

Django працює за архітектурою MVT: Model, View, Template.

### Model
Model відповідає за дані та взаємодію з базою даних. У моделі описуються таблиці, поля, зв’язки та правила зберігання даних.

### View
View приймає HTTP-запит, обробляє його, звертається до моделі за даними та формує відповідь. У Django view — це не обов’язково клас; часто це звичайна функція.

### Template
Template відповідає за відображення даних користувачу. Це HTML-файл із шаблонним синтаксисом Django.

### Як усе працює разом
1. Користувач надсилає запит через браузер.
1. Django зіставляє URL-адресу запиту за допомогою файлу urls.py.
1. view  обробляє запит.
1. view  взаємодіє з моделями для отримання або оновлення даних.
1. view  передає дані до шаблону.
1. Шаблон генерує HTML-код.
1. Django повертає відрендерену відповідь до браузера.

MVT дуже зручна для навчання, бо чітко розділяє відповідальність між даними, логікою та відображенням.

## Структура Django-проєкту

Коли ви створюєте Django-проєкт, він має стандартну структуру. На рівні проєкту є налаштування, маршрути, команди керування, а всередині — окремі застосунки.

Приблизна структура:

```text
myproject/
├── manage.py
├── myproject/
│   ├── __init__.py
│   ├── settings.py
│   ├── urls.py
│   ├── asgi.py
│   └── wsgi.py
└── app/
    ├── migrations/
    ├── __init__.py
    ├── admin.py
    ├── apps.py
    ├── models.py
    ├── views.py
    └── tests.py
```

### Що означає кожен файл
- `manage.py` — командний інтерфейс для керування проєктом.
- `settings.py` — головні налаштування Django-проєкту.
- `urls.py` — маршрутизація URL.
- `asgi.py` і `wsgi.py` — точки входу для серверів розгортання.
- `models.py` — моделі даних.
- `views.py` — логіка обробки запитів.
- `admin.py` — налаштування адмін-панелі.
- `apps.py` — конфігурація застосунку.
- `migrations/` — історія змін у базі даних.

***

## Структура застосунку

Django-проєкт може містити кілька застосунків. Застосунок — це окрема частина проєкту, яка відповідає за певний функціональний блок: користувачів, задачі, блог, замовлення, товари тощо.

Наприклад, у проєкті “expense tracker” можна мати:
- `users` — облік користувачів;
- `transactions` — облік транзакцій;
- `budgets` — бюджети;
- `reports` — звіти.

Такий підхід допомагає:
- не змішувати всю логіку в одному місці;
- легше підтримувати код;
- простіше масштабувати проєкт;
- зручніше працювати в команді.

## Створення проєкту

Щоб створити новий Django-проєкт, використовується команда:

```bash
django-admin startproject myproject
```

Після цього з’явиться структура з `manage.py` і папкою проєкту.

### Приклад створення в поточній папці
```bash
django-admin startproject config .
```

Точка в кінці означає, що проєкт створюється у поточній директорії.

### Запуск сервера
```bash
python manage.py runserver
```

Після запуску сервер зазвичай доступний за адресою `http://127.0.0.1:8000/`.

***

## Створення застосунку

Після створення проєкту зазвичай додають окремі застосунки.

### Команда створення застосунку
```bash
python manage.py startapp core
```

Після цього з’являється папка `core` з базовими файлами застосунку.

### Підключення застосунку
Щоб Django “побачив” новий застосунок, його потрібно додати до `INSTALLED_APPS` у `settings.py`.

```python
INSTALLED_APPS = [
    "django.contrib.admin",
    "django.contrib.auth",
    "django.contrib.contenttypes",
    "django.contrib.sessions",
    "django.contrib.messages",
    "django.contrib.staticfiles",
    "core",
]
```

## Файл settings.py

`settings.py` — це центральний файл налаштувань проєкту. Тут зберігаються параметри, без яких Django не зможе нормально працювати. 

### Основні налаштування
- `INSTALLED_APPS` — список підключених застосунків.
- `MIDDLEWARE` — список middleware.
- `DATABASES` — налаштування бази даних.
- `TEMPLATES` — налаштування шаблонів.
- `STATIC_URL` — адреса для статичних файлів.
- `LANGUAGE_CODE` — мова проєкту.
- `TIME_ZONE` — часовий пояс.
- `DEBUG` — режим розробки.
- `ALLOWED_HOSTS` — дозволені домени.

### Приклад важливих налаштувань
```python
DEBUG = True
LANGUAGE_CODE = "uk"
TIME_ZONE = "Europe/Kyiv"
STATIC_URL = "static/"
```

### Підключення шаблонів
```python
TEMPLATES = [
    {
        "BACKEND": "django.template.backends.django.DjangoTemplates",
        "DIRS": ["templates"],
        "APP_DIRS": True,
        "OPTIONS": {
            "context_processors": [
                "django.template.context_processors.request",
            ],
        },
    },
]
```

`settings.py` не варто редагувати хаотично. Краще розуміти, яка частина налаштувань за що відповідає.

## Команда manage.py

`manage.py` — це файл, через який виконуються адміністративні команди Django. Він дозволяє створювати застосунки, запускати сервер, робити міграції, відкривати shell і виконувати інші дії. 

### Найчастіші команди
```bash
python manage.py runserver
python manage.py startapp core
python manage.py makemigrations
python manage.py migrate
python manage.py createsuperuser
python manage.py shell
python manage.py showmigrations
```

### Що роблять ці команди
- `runserver` — запускає сервер розробки;
- `startapp` — створює новий застосунок;
- `makemigrations` — створює файли міграцій;
- `migrate` — застосовує міграції до бази;
- `createsuperuser` — створює адміністратора;
- `shell` — відкриває інтерактивну консоль Django;
- `showmigrations` — показує список міграцій.

`manage.py` — одна з найважливіших точок входу в Django-проєкт, тому студент має вміти працювати з ним без підказок.

## Приклад першого проєкту

Нижче наведено мінімальний приклад створення Django-проєкту і застосунку.

### 1. Створити проєкт
```bash
django-admin startproject config .
```

### 2. Створити застосунок
```bash
python manage.py startapp core
```

### 3. Додати застосунок у settings.py
```python
INSTALLED_APPS = [
    ...
    "core",
]
```

### 4. Створити простий view
```python
from django.http import HttpResponse

def home(request):
    return HttpResponse("Hello, Django!")
```

### 5. Прописати маршрут
```python
from django.contrib import admin
from django.urls import path
from core.views import home

urlpatterns = [
    path("admin/", admin.site.urls),
    path("", home),
]
```

### 6. Запустити сервер
```bash
python manage.py runserver
```

Після цього при відкритті головної сторінки браузер покаже `Hello, Django!`.
