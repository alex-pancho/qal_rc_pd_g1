# Заняття 50. Розгортання Django-застосунку (2 години)

## Мета заняття

На завершальному занятті курсу студенти виконають повне розгортання власного Django-проєкту на сервері або хмарній платформі, підключать базу даних PostgreSQL, проведуть фінальне тестування та підготують застосунок до демонстрації і захисту.

Після цього заняття кожен студент матиме повністю працюючий веб-застосунок, доступний через Інтернет.

---

# 1. Підготовка до розгортання

Перед початком деплою необхідно переконатися, що проєкт повністю готовий.

Перевіряємо:

* усі зміни закомічені до Git;
* міграції створені та застосовані;
* відсутні критичні помилки;
* файл `.env` містить усі необхідні налаштування;
* застосунок запускається локально без помилок.

Команди перевірки:

```bash
python manage.py check
python manage.py makemigrations
python manage.py migrate
python manage.py test
```

---

# 2. Вибір середовища розгортання

Для навчальних проєктів існує кілька популярних варіантів.

### Хмарні платформи

* Railway
* Render
* Fly.io
* PythonAnywhere

Переваги:

### VPS

Приклади:

Недолік — необхідно самостійно налаштовувати сервер.

---

# 3. Підключення PostgreSQL

Після створення сервера бази даних необхідно отримати:

* адресу сервера;
* порт;
* назву бази;
* ім'я користувача;
* пароль.

У Django змінюємо налаштування:

```python
DATABASES = {
    "default": {
        "ENGINE": "django.db.backends.postgresql",
        "NAME": os.getenv("DB_NAME"),
        "USER": os.getenv("DB_USER"),
        "PASSWORD": os.getenv("DB_PASSWORD"),
        "HOST": os.getenv("DB_HOST"),
        "PORT": os.getenv("DB_PORT"),
    }
}
```

Після цього виконуємо:

```bash
python manage.py migrate
```

Усі таблиці будуть створені автоматично.

---

# 4. Створення адміністратора

Після міграцій необхідно створити суперкористувача.

```bash
python manage.py createsuperuser
```

Вводимо:

* логін;
* email;
* пароль.

Після запуску сервера адміністратор зможе входити до панелі:

```
/admin/
```

---

# 5. Завантаження статичних файлів

Перед запуском Production необхідно зібрати всі CSS, JavaScript та зображення.

```bash
python manage.py collectstatic
```

Усі файли буде скопійовано до каталогу:

```
STATIC_ROOT
```

Саме звідти їх буде обслуговувати вебсервер.

Після запуску необхідно протестувати всі основні сценарії роботи.

Перевіряємо:

* реєстрацію;
* авторизацію;

# 7. Фінальне тестування проєкту

Перед здачею курсового проєкту проводиться повна перевірка.

### Smoke Testing

Перевіряємо:

* чи запускається сайт;
* чи відкриваються сторінки;
* чи працює база даних.

---

### Functional Testing

Перевіряємо бізнес-логіку:

* CRUD-операції;
* авторизацію;
* права доступу;
* роботу форм;
* API.

---

### Regression Testing

Переконуємося, що останні зміни не зламали вже реалізований функціонал.

---

### API Testing

Якщо використовується Django REST Framework:

* Swagger;
* Postman;
* автоматичні тести `pytest`.

---

# 8. Оптимізація продуктивності

Навіть навчальний проєкт повинен працювати швидко.

Основні рекомендації:

* використовувати індекси PostgreSQL;
* уникати зайвих SQL-запитів;
* застосовувати `select_related()` і `prefetch_related()`;
* кешувати дані за потреби;
* оптимізувати розмір зображень;
* мінімізувати CSS і JavaScript;
* використовувати пагінацію.

---

# 9. Типові проблеми після розгортання

Найпоширеніші помилки:

**Помилка 500**

Причини:

* неправильні змінні середовища;
* помилка в коді;
* міграції не застосовані.

---

**Не працюють стилі**

Причини:

* не виконано `collectstatic`;
* неправильно налаштований `STATIC_ROOT`;
* помилки у вебсервері.

---

**Не працює база даних**

Причини:

* неправильний пароль;
* заблокований порт;
* сервер PostgreSQL недоступний.

---

**Помилка CSRF**

Причини:

* неправильний домен;
* відсутній HTTPS;
* не налаштовано `CSRF_TRUSTED_ORIGINS`.

---

# 10. Звіти про помилки (Bug Reports)

Перед захистом проєкту всі знайдені дефекти бажано документувати.

Типовий Bug Report містить:

* ID помилки;
* коротку назву;
* середовище;
* кроки відтворення;
* очікуваний результат;
* фактичний результат;
* пріоритет;
* серйозність;
* скріншоти або логи.

Навіть якщо проєкт навчальний, якісне оформлення звітів демонструє професійний підхід до тестування.

---

# 11. Підготовка проєкту до захисту

Перед презентацією необхідно перевірити:

* проєкт запускається без помилок;
* усі залежності описані в `requirements.txt`;
* репозиторій містить актуальний `README.md`;
* створено адміністратора;
* база даних працює;
* API документоване;
* застосунок доступний через Інтернет;
* код оформлено відповідно до PEP 8;
* усі зміни завантажено до GitHub.

9. Підготують README з інструкцією запуску.
