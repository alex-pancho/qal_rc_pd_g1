# Домашнє завдання: Модулі та Пакети

## Контекст

Вернадський вів детальні щоденники досліджень, класифікував мінерали, записував спостереження, систематизував дані. Саме так і має виглядати добре організований пакет: кожен модуль знає свою ділянку роботи, нічого не перемішується, і з будь-якого місця зрозуміло, де що шукати.

## Завдання: Пакет `vernadsky_lab`

Ти створюєш цифровий архів науково-дослідної лабораторії. Дослідники реєструють зразки мінералів, записують спостереження і формують звіти.

### 📁 Очікувана структура:

```
vernadsky_lab/
    __init__.py
    minerals.py
    observations.py
    reports.py
    utils.py
main.py
```

### Модуль `minerals.py`

Каталог мінералів лабораторії.

**Словник `MINERAL_CATALOG`** — мінімум 5 записів у форматі:

```python
{
    "назва": {
        "formula": "хімічна формула",
        "hardness": число від 1 до 10,   # шкала Мооса
        "origin": "місце знахідки",
        "discovered": рік
    }
}
```

**Функція `get_mineral(name)`:**
* повертає словник із даними про мінерал
* якщо не знайдено — повертає `None`

**Функція `register_mineral(name, formula, hardness, origin, discovered)`:**
* додає новий мінерал до каталогу
* якщо такий вже є — повертає `"Мінерал '<name>' вже зареєстровано в каталозі"`
* якщо `hardness` поза межами 1–10 — повертає `"Некоректна твердість: має бути від 1 до 10"`
* інакше — повертає `"Мінерал '<name>' додано до каталогу"`

### Модуль `observations.py`

Журнал наукових спостережень.

**Список `_journal`** — внутрішній, не доступний напряму ззовні (починається з `_`). Спочатку порожній.

**Функція `record(researcher, mineral_name, note)`:**
* імпортує `get_mineral` із `minerals.py`
* якщо мінерал не знайдено в каталозі — повертає `"Мінерал '<mineral_name>' не зареєстровано. Спочатку додайте його до каталогу"`
* інакше — додає запис до журналу у вигляді словника з полями: дослідник, мінерал, нотатка, та дата (використай `datetime.date.today()`)
* повертає `"Спостереження записано: <researcher> → <mineral_name>"`

**Функція `get_observations(mineral_name=None)`:**
* якщо `mineral_name` передано — повертає лише записи про цей мінерал
* якщо не передано — повертає всі записи журналу
* якщо журнал порожній або записів не знайдено — повертає порожній список

### Модуль `reports.py`

Формування наукових звітів.

**Функція `summary()`:**
* імпортує `MINERAL_CATALOG` із `minerals.py` та `get_observations` із `observations.py`
* повертає рядок із трьома блоками:
  * кількість мінералів у каталозі
  * кількість спостережень у журналі
  * найактивніший дослідник (той, хто зробив найбільше записів), або `"Спостережень ще немає"` якщо журнал порожній

**Функція `mineral_report(name)`:**
* повертає повний звіт по одному мінералу:
  * усі дані з каталогу
  * усі спостереження по ньому
  * якщо мінерал не знайдено — `"Мінерал '<name>' відсутній у каталозі"`

### Модуль `utils.py`

Допоміжні інструменти.

**Функція `hardest_minerals(n=3)`:**
* імпортує `MINERAL_CATALOG` із `minerals.py`
* повертає список назв `n` найтвердіших мінералів за шкалою Мооса (за спаданням)

**Функція `search_by_origin(origin_keyword)`:**
* повертає список назв мінералів, у полі `origin` яких зустрічається `origin_keyword` (без урахування регістру)
* якщо нічого не знайдено — порожній список

### Файл `__init__.py`

Виставляє назовні лише публічний інтерфейс пакету — чотири функції:

```python
from vernadsky_lab import register_mineral, record, summary, mineral_report
```

Решта — внутрішні деталі пакету.

### Файл `main.py`

Точка входу. Жодної логіки — лише виклики. Має продемонструвати повний цикл роботи лабораторії:

* реєстрацію двох нових мінералів
* спробу зареєструвати дублікат
* запис трьох спостережень від різних дослідників
* спробу записати спостереження для незареєстрованого мінералу
* вивід загального зведення
* вивід детального звіту по одному мінералу

## На що звернути увагу

* `observations.py` залежить від `minerals.py` — і це нормально, але не навпаки: залежності мають йти в один бік
* `_journal` починається з підкреслення — це сигнал, що це внутрішній стан модуля, не для прямого використання ззовні
* `__init__.py` — це редактор каталогу: він вирішує, що публікується, а що залишається внутрішньою справою лабораторії
* Уся логіка — у модулях. `main.py` лише «натискає кнопки»

## Бонус 🏆

Додай модуль `export.py` із функцією `to_csv(filename)`, яка експортує весь журнал спостережень у `.csv` файл із колонками `date`, `researcher`, `mineral`, `note`. Підключи її через `__init__.py` і викличте з `main.py` після всіх записів.
